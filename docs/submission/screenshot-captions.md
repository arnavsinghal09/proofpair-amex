# Prototype screenshot captions

These captions are written for evaluators and map one-to-one to the final capture filenames.

1. **Command center — operational pressure before case detail.** Synthetic workload, SLA exposure, queue state and recent activity establish the analyst’s next action without collapsing the product into a chatbot.
2. **Dispute queue — evidence-aware triage.** Search, saved views, configurable columns, selection and bulk routing support real operating work across ownership, age, reason code and evidence state.
3. **Case overview — one record, both parties.** Transaction facts, narrative, member position, merchant position, chronology and review tasks remain visible in the same case context.
4. **Evidence room — provenance before persuasion.** Required-record coverage, verification state, source detail and contradictions make the basis of the recommendation inspectable.
5. **Decision studio — governed recommendation.** A version-pinned reason pack exposes required evidence, contradiction status, party signal ledger, minimum gap, rationale and receipt controls.
6. **Specialist route — failure is a product state.** When verified records conflict or remain incomplete, ProofPair names the blocker and routes the case without issuing a recommendation or taking account action.
7. **Decision receipt — the explanation is portable.** The recommended next step, parties, amount, versioned policy and every control result are packaged into an inspectable receipt.
8. **Conflict counterfactual — arithmetic never overrides ambiguity.** Introducing a new unresolved contradiction preserves the source scores but fails the contradiction gate and routes the case.
9. **Missing-record counterfactual — abstention is explicit.** Removing a required verified record changes Required Evidence Complete to REVIEW and forces specialist handling.
10. **Ambiguous 4554 case — specialist routing is not an error state.** Strong evidence exists on both sides, but unresolved custody facts prevent an automated recommendation.
11. **Communications — controlled two-party outreach.** Analysts can switch audience, edit an evidence request and set a response deadline; no message leaves the prototype.
12. **Audit trail — decision intent is reconstructable.** Case creation, evidence normalization, contradiction checking and recommendation creation sit beside all four behavioral checks.
13. **Portfolio intelligence — operational visibility without fake ROI.** Exposure, readiness and routing are summarized while savings, accuracy and cycle-time claims are explicitly withheld.
14. **Governance — controls precede automation.** Five active rule packs, 24/24 synthetic property checks, human authority and integration boundaries are visible in one surface.
15. **Policy change log — versions are reviewable.** Each active reason pack carries a visible version and prototype-local change history.
16. **Notifications — alerts return analysts to the control point.** SLA and conflict warnings lead to the relevant decision or evidence workspace.
17. **Mobile command center — the hierarchy survives.** Priority actions, essential metrics and navigation remain legible at 390×844.
18. **Mobile case — full review context remains reachable.** Case identity, reason code, amount, SLA and workspace navigation stay usable on a narrow viewport.

## Screenshot truth note

All names, merchants, cases, evidence and metrics are fictional. Screenshots demonstrate implemented browser-session workflows against synthetic fixtures. External connectors, authentication, persistence, outbound delivery and financial actions are not implemented.
